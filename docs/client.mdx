# Client Configuration

The `GLabsClient` is the main entry point for all SDK operations.

## Constructor

```typescript
import { GLabsClient } from '@getvrex/glabs-sdk';

const client = new GLabsClient({
  bearerToken: 'your-token',
  sessionToken: 'your-session-token',
  accountTier: 'pro',
  projectId: 'your-project-id',
  recaptcha: { provider: 'regotcha', apiKey: 'key' },
  timeout: 120000,
  maxRetries: 2,
  retryDelay: 1500,
  logger: console,
});
```

## Configuration Options

```typescript
type GLabsClientConfig = {
  bearerToken: string;         // Required: auth token for Google Labs APIs
  sessionToken?: string;       // Session token for auto token refresh (ST→AT)
  accountTier?: AccountTier;   // 'pro' | 'ultra' (default: 'pro')
  projectId?: string;          // Default project ID (auto-resolved if omitted)
  recaptcha?: RecaptchaConfig; // reCAPTCHA provider config
  logger?: GLabsLogger;        // Custom logger (default: console)
  timeout?: number;            // Request timeout ms (default: 120000)
  maxRetries?: number;         // Network error retries (default: 2)
  retryDelay?: number;         // Retry delay ms (default: 1500)
};
```

### bearerToken

Required. The Google Labs API access token. Used for all image and video generation requests.

If you also provide `sessionToken`, the SDK will automatically refresh `bearerToken` when it expires or approaches expiration.

### sessionToken

The `__Secure-next-auth.session-token` cookie value from `labs.google`. When provided:

- SDK proactively refreshes bearer token 1 hour before expiry
- On 401 responses, SDK auto-refreshes and retries the request once
- Enables `client.refreshToken()` for manual refresh

See [Token Management](/docs/glabs-sdk/token-management) for details.

### accountTier

Controls which video models and features are used:

| Feature | Pro | Ultra |
|---------|-----|-------|
| Default Video Mode | `fast` | `quality` |
| Video Modes | quality, fast | quality, fast |
| HD/4K Upscaling | Yes | Yes |
| Max Images Per Batch | 4 | 4 |
| PaygateTier | `PAYGATE_TIER_ONE` | `PAYGATE_TIER_TWO` |
| Ultra Models | No | Yes (fast mode) |

```typescript
// Pro: uses standard Veo 3.1 models
const proClient = new GLabsClient({ bearerToken: 'token', accountTier: 'pro' });

// Ultra: uses _ultra model variants in fast mode
const ultraClient = new GLabsClient({ bearerToken: 'token', accountTier: 'ultra' });
```

### projectId

Optional default project ID for generation requests. If omitted, the SDK auto-resolves by fetching your first available project via the Project API (requires `sessionToken`).

Auto-resolution priority:
1. `projectId` passed in the method call
2. `projectId` from client config
3. First project from `projects.getFirstProjectId()` (cached)

### recaptcha

Required for image and video generation. See [reCAPTCHA Configuration](/docs/glabs-sdk/recaptcha).

## Client Properties

```typescript
client.accountTier;  // 'pro' | 'ultra'
client.projectId;    // string | undefined
```

## Client Methods

### refreshToken()

Manually refresh the bearer token using the session token.

```typescript
await client.refreshToken();
```

Throws `GLabsError` if no `sessionToken` is configured.

### close()

Close persistent resources (e.g., Chrome browser for reCAPTCHA). Call this when you're done with the client.

```typescript
await client.close();
```

### generateSessionId() (static)

Generate a session ID in Google's expected format.

```typescript
const sessionId = GLabsClient.generateSessionId();
// Returns: ";1709123456789"
```

## Service Namespaces

The client exposes four service namespaces:

| Namespace | Methods |
|-----------|---------|
| `client.projects` | `list()`, `get()`, `getFirstProjectId()`, `clearCache()` |
| `client.images` | `generate()`, `upload()`, `upsampleImage()`, `getCreditStatus()` |
| `client.videos` | `generateTextToVideo()`, `generateImageToVideo()`, `generateReferenceImagesVideo()`, `extend()`, `reshoot()`, `upsample()`, `checkStatus()`, `pollOperation()` |

All generation methods automatically:
- Refresh the bearer token if `sessionToken` is configured
- Retry once on 401 after refreshing
- Resolve `projectId` if not provided

## Custom Logger

```typescript
type GLabsLogger = {
  log: (message: string, ...args: unknown[]) => void;
  warn: (message: string, ...args: unknown[]) => void;
  error: (message: string, ...args: unknown[]) => void;
};
```

### Custom logger example

```typescript
const client = new GLabsClient({
  bearerToken: 'token',
  logger: {
    log: (msg, ...args) => console.log(`[GLabs] ${msg}`, ...args),
    warn: (msg, ...args) => console.warn(`[GLabs] ${msg}`, ...args),
    error: (msg, ...args) => console.error(`[GLabs] ${msg}`, ...args),
  },
});
```

### Silent mode

```typescript
const client = new GLabsClient({
  bearerToken: 'token',
  logger: { log: () => {}, warn: () => {}, error: () => {} },
});
```

## Retry Configuration

The SDK automatically retries on network errors (fetch failures, timeouts, connection refused):

```typescript
const client = new GLabsClient({
  bearerToken: 'token',
  maxRetries: 3,      // retry attempts (default: 2)
  retryDelay: 2000,   // delay between retries in ms (default: 1500)
  timeout: 180000,    // request timeout in ms (default: 120000)
});
```
